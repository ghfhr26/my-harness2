# 하네스 파이프라인 (R3)

## 단계

| 단계 | story-work 문장 | 입력 | 출력 | 다음으로 넘어가는 조건 |
|---|---|---|---|---|
| S1 레퍼런스 | 1, 2 | 대상 화면명, 유저스토리 번호 | 레퍼런스 수집본, 반영 항목 | 게이트 G1 (자동) |
| S2 화면설계 | 3 | 반영 항목 | 화면설계서 | 게이트 G2 (자동) |
| S3 키스크린 | 4, 5 | 화면설계서 | 키스크린 (390×844) | 게이트 G3 (사람 컨펌 ★) |
| S4 제작 | 6 | 확정 시안 | 토큰·컴포넌트, 완성 시안 | 게이트 G4 (자동) |
| S5 검토 | 7 | 완성 시안 | 위반 리포트 | 위반 0건이면 완료 |

게이트별 통과 조건은 R5에서 정한다.

## 키스크린 선정 규칙 (S3)

- 키스크린은 항상 2~3개다 (`story-work.md` 문장 4). 대상 화면이 1개인 입력은 G0-2에서 받지 않는다.
- 대상 화면이 2~3개: 전부 키스크린으로 그린다.
- 대상 화면이 4개 이상: 입력한 유저스토리 번호마다 1개씩 고른다.
  - 합계가 3개를 넘으면 유저스토리 번호가 작은 순으로 3개까지.
  - 합계가 2개 미만이면 대상 화면 입력 순서대로 2개가 될 때까지 채운다.
- 고른 화면은 반드시 대상 화면 목록 안에 있어야 한다.

## 되돌아가는 지점

| 발생 위치 | 조건 | 복귀 단계 | 한도 |
|---|---|---|---|
| G3 컨펌 반려 | 사유 코드 `visual` | S3 키스크린 | 없음 (사람 판단) |
| G3 컨펌 반려 | 사유 코드 `structure` | S2 화면설계 | 없음 (사람 판단) |
| G3 컨펌 반려 | 사유 코드 `direction` | S1 레퍼런스 | 없음 (사람 판단) |
| S5 검토 | 위반 1건 이상 | S4 제작 | 3회. 3회째에도 위반이 남으면 중단하고 실행자에게 리포트 |
| G1, G2, G4 자동 게이트 | 미통과 | 해당 게이트 직전 단계 | R5에서 결정 |

- 반려 기록에는 사유 코드를 정확히 1개 적는다. 0개 또는 2개 이상이면 복귀하지 않고 다시 묻는다.
- 복귀하면 복귀 단계 이후의 산출물은 전부 다시 만든다.
