# 하네스 검증과 리뷰 (R8)

## 1. 판정 스크립트 검증 (하네스를 쓰기 전)
- `tests/pass/`: 모든 게이트를 통과하는 정상 실행 폴더 1세트.
- `tests/fail/<규칙 ID>/`: 그 규칙 하나만 어긴 샘플. 규칙 ID마다 1개 이상. 같은 규칙에 여러 개면 `<규칙 ID>--<설명>`.
- 샘플의 `figma/` 폴더는 Figma REST API 응답과 같은 모양이다. 검증은 실제 판정과 같은 코드로 이 응답을 읽는다.
- 샘플은 `tests/make_fixtures.py`가 만든다. `test_gates.py`가 매번 다시 만들어 현재 `design.md`와 맞춘다.
- 서체 대체 샘플: `tests/fail/T-1--font-fallback/` (PNoto Sans KR 대신 Inter로 바뀐 텍스트).
- `scripts/test_gates.py`가 센다:
  - 정상 세트에서 모든 규칙의 위반이 0건
  - 위반 샘플마다 해당 규칙 ID로 정확히 1건, 다른 규칙 ID로 0건
- 샘플 없는 규칙 0건. `scripts/gate.py`의 규칙 ID와 `docs/harness-gates.md`의 규칙 ID가 같아야 한다.
- `guard.py`도 검사한다: 허용 경로는 통과, 차단 경로는 차단.
- 전부 통과하면 `.harness/tests-ok.json`에 기록한다. 이 기록이 현재 `docs/`, `rules/`, `scripts/`와 맞지 않으면 `디자인 시작`을 받지 않는다.
- `docs/harness-gates.md`나 `scripts/gate.py`를 고치면 다시 전부 돌린다.

## 2. 시험 실행 (스크립트 검증 통과 후 1회)
- 입력: `디자인 시작: 내 자산, 자산 상세 / 스토리 3, 4`
- 확인할 것:
  - S1부터 S5까지 끝까지 간다
  - G3에서 멈추고 컨펌을 기다린다
  - `컨펌 반려 visual`을 1회 넣으면 S3로 복귀한다
  - 멈춘 뒤 `이어서`로 재개된다
  - ★A-1, ★A-2, ★B-1이 검사 결과에 나온다 (건너뜀 0건)
- 시험 실행의 Figma 페이지와 실행 폴더는 지우지 않고 남긴다.

## 3. 컨펌 때 사람 문항 (스크립트가 못 세는 것)
G3 컨펌 요청에 아래 3문항을 같이 보여준다. 출처는 `docs/prd.md` §15.

| # | 문항 | 근거 |
|---|---|---|
| Q1 | 처음 보는 사람이 이 화면에서 무엇을 할 수 있는지 설명 없이 알 수 있는가 | §15 디자인 완성도 |
| Q2 | 자료실이 아니라 실험실·자산 라이브러리처럼 보이는가 | §15 디자인 완성도 |
| Q3 | 권한과 상태의 차이가 화면에서 구분되는가 (단순 나열이 아닌가) | §15 문제 해결의 완성도 |

- `컨펌 승인 <이름>`을 받으면 3문항의 예/아니오를 묻고 `approval.json`에 적는다.
- 3개 모두 `예`여야 승인이 기록된다. `아니오`가 1개라도 있으면 승인하지 않고 반려 사유 코드를 묻는다.
- 사람 승인 지점은 여전히 G3 1곳이다.

## 4. 하네스 리뷰
- 실행이 끝나거나 한도 초과로 멈출 때마다 `runs/summary.csv`에 1줄을 추가한다.
  - 열: 날짜, 실행 폴더명, 대상 화면, 결과(완료/중단), 게이트별 재시도 횟수, S5→S4 복귀 횟수, 규칙 ID별 위반 건수, 컨펌 반려 사유 코드
- 완료된 실행이 5개 쌓일 때마다 위반 건수 상위 규칙 3개와 재시도 횟수가 가장 많은 게이트 1개를 보여준다.
- 리뷰에서 고칠 대상은 에이전트 지시문 또는 게이트 조건이다. 수정은 실행자 승인 후에 하고, 조건을 고쳤으면 1번 검증을 다시 돌린다.
