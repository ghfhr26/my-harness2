## 레퍼런스에서 실제로 본 것

각 레퍼런스에서 확인한 화면은 검색 결과의 대표 화면 1장이다. 아래 서술은 그 1장에서 본 내용이다.

| ID | 앱 | 본 것 |
|---|---|---|
| R-01 | 당근 | "나의 판매내역" 제목 아래 "글쓰기" 버튼, 그 아래 탭 3개(판매중 / 거래완료 5 / 숨김), 빈 상태 한 줄 문구 |
| R-02 | 니콘내콘 | 판매내역. 탭 2개(진행중 / 완료) 아래 필 칩(전체 / 검수중 / 검수완료 / 정산예정), 빈 상태에 일러스트 + 문구 + 버튼 1개 |
| R-03 | 플리더스 | "나의 테스트 참여 현황". 썸네일마다 바로 아래 같은 위치에 상태 필(진행중 / 심사중 / 반려). 앱스토어 소개 이미지 안의 화면이다 |
| R-04 | 쑥쑥찰칵 | 설정 카드. "댓글 공개 범위 — 현재 값 — 꺾쇠" 한 줄, 필드 아래 배경이 구분된 안내 상자, 구성원 행의 권한 태그 |
| R-05 | 정오의데이트 | "프로필이 심사중입니다" 굵은 한 줄 + 아래 보조 문구로 처리 예상 안내. 화면 일부가 알림 팝업에 가려져 있다 |
| R-06 | 투두메이트 | 개인정보 보호 설정. 항목마다 오른쪽에 현재 값, 구역 아래 회색 설명 문구 |
| R-07 | 달다방 | 상품 상세. 이미지, 브랜드, 제목, 태그 줄, 가격 순서. 하단 고정 바에 액션 버튼 |
| R-08 | 럽맘 | 체크리스트. 필 칩 필터 아래 항목 카드(왼쪽 체크박스, 제목, 태그와 날짜). 체크한 항목은 취소선 |
| R-09 | 다글로 | 가입 동의. "모두 동의" 아래 [필수]/[선택] 항목, 하단 "다음" 버튼이 비활성 상태 |
| R-10 | 라우드소싱 | 콘테스트 목록. 상태 칩(진행중 / 심사중 / 종료), 행은 왼쪽 썸네일 + 분류, 제목, 두 줄 요약, 메타, 맨 아래 배지 |

## 가져오지 않은 것 (A·B와 부딪힘)

- **R-06 투두메이트의 기본값 "모든 사람"**: 공개가 기본인 패턴이라 A(기본 비공개)에 어긋난다. A-09는 설명 문구의 위치만 가져온다. 공개 범위의 기본값은 `비공개`다.
- **R-09 다글로의 "모두 동의" 일괄 체크**: 한 번에 전부 체크하면 판매 기준을 항목별로 확인한다는 체크리스트의 목적(PRD §6-7, B)이 무너진다. A-12는 "전부 체크 전 버튼 비활성"만 가져온다.
- **R-01 당근의 글 작성 즉시 "판매중"**: 검수 없이 바로 판매되는 흐름이라 B에 어긋난다. A-01, A-02는 건수 표시와 등록 버튼 위치만 가져온다. 상태 이름도 가져오지 않는다.
- **R-02 니콘내콘의 "정산예정", R-07 달다방의 가격·구매 버튼**: 결제·정산·구매는 Phase 2~3이라 이번 범위 밖이다. A-10은 하단 고정 바라는 구조만 가져오고, 거기 들어갈 버튼은 PRD §6-5 범위 안에서 정한다.
- **R-05 정오의데이트의 처리 시간 약속("보통 3시간")**: PRD에 검수 소요 시간이 없어 가져오지 않는다. A-08은 "다음에 일어날 일" 안내까지만이다.
- 상태값은 레퍼런스의 표현(심사중, 검수중 등)을 쓰지 않고 PRD §6-5의 5개(임시저장, 검수 대기, 수정 요청, 승인됨, 반려)만 쓴다.

## 찾지 못한 것

uibowl 무료 조회 한도(하루 10회)에 걸려 첫 6회 검색 뒤로는 결과를 받지 못했다. 아래는 레퍼런스가 없어 반영 항목으로 만들지 않았다. 설계서에서는 PRD와 `design.md`를 근거로 정해야 한다.

- **검수 액션 3개(승인 / 수정 요청 / 반려)의 버튼 배치**: "승인 거절" 문구 검색이 한도에 막혔다. 레퍼런스 없음.
- **수정 요청 코멘트 입력란**: "수정 요청" 문구 검색이 한도에 막혔다. 레퍼런스 없음.
- **자산 카드의 공개 범위 표시(비공개 / 멤버 공개)**: "비공개" 배지 검색이 한도에 막혔다. R-04의 권한 태그가 가장 가깝지만 자산 카드 사례는 아니어서 항목으로 올리지 않았다.
- **파일 첨부 목록, 가격 설정·승인 입력**: 검색하지 못했다.

## 스토리 인용에 대해

`input.json`의 스토리는 3, 4뿐이고 운영자 스토리(5)는 없다. 운영자 검수 화면의 항목 A-11~A-14는 스토리 4("판매 신청하고, 그 상태를 확인한다")에 묶었다. 멤버가 확인하는 상태(검수 대기, 수정 요청, 승인됨, 반려)가 이 화면의 체크리스트와 검수 결과로 정해진다는 근거다.
